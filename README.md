# CS50 TSE Querier - README

## Assumptions

- `pageDirectory` is a crawler-produced directory (contains `.crawler` and files named 1, 2, 3, ... without gaps).
- `indexFilename` points to an index file generated by the TSE indexer and corresponds to the provided `pageDirectory`.
- Input queries contain only letters and whitespace; characters outside that set are rejected per the spec.
- Query syntax follows the BNF: words optionally separated by `and` / `or`, with `and` taking precedence.
- The index never contains words shorter than 3 characters, so such queries naturally return no matches.
- Standard output is reserved for prompts, cleaned queries, match summaries, and ranked results exactly as specified.

## Implementation notes

- Command-line parsing is centralized in `parseArgs()` which validates argument count, crawler directory, and readable index file.
- The index is loaded once at startup via `index_load()` and reused for all subsequent queries.
- Each input line is validated character-by-character, tokenized, normalized to lowercase, and reprinted as a "clean" query.
- The evaluator treats implicit AND between adjacent words, enforces precedence by scanning AND-sequences inside OR-separated groups, and leverages `counters_t` for intermediate results.
- Counter merges are handled through a unified helper that supports copying, intersections (minimum counts), and unions (sum counts).
- Ranking uses a selection-sort style loop: repeatedly find the highest scoring doc, print it with its URL (via `pagedir_load()`), and zero that entry.
- The `testing.sh` script mirrors crawler/indexer style: it stresses argument validation, malformed queries, and representative valid queries using the sample `letters-2` data.

## Functionality implemented

- Full requirements coverage from the Querier spec: argument validation, query normalization/printing, syntax checking, AND/OR evaluation, ranking, and URL lookup.
- Graceful handling of malformed inputs (bad characters, leading/trailing/adjacent operators, empty lines).
- Defensive programming with NULL guards and descriptive error messages written to stderr.
- Memory hygiene through `mem_malloc`/`counters_new` wrappers plus cleanup of temporary counters and getline buffers.

## Testing

- Automated script `testing.sh` exercises:
	- Missing/extra arguments, invalid directories, unreadable index files.
	- Query-level errors (bad characters, invalid operator placement, implicit AND precedence).
	- Valid queries (single/multi word, AND/OR combinations, regression list piped via stdin).
- Manual spot checks against sample indices to confirm ranked output and URL retrieval.
- `make -C querier test` runs the script under Bash with `set -u` enabled for stricter failure detection.

## Known issues

- When run against indices with no matches for the provided queries, the output will repeatedly report "No documents match."—this is expected.
- The current ranking loop loads each matching document file to obtain its URL; on very large result sets this adds disk I/O overhead but keeps implementation simple.

## Compilation

To build only the querier (and ensure dependent libraries are available):

```bash
make -C querier
```

To run the regression test suite:

```bash
make -C querier test
```

To clean:

```bash
make -C querier clean
```

## Usage

```bash
./querier pageDirectory indexFilename
```

Example:

```bash
./querier ../data/letters-2 ../data/letters-2.index
```

Queries are typed interactively (one per line) until EOF; the program prints cleaned queries, diagnostics, and ranked matches per the spec.
